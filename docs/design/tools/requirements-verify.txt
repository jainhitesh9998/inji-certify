# Python environment for docs/design/tools/verify_mdoc.py — the CI second opinion on issued mDocs
# (docs/design/20-mdl-issuer.md M-01, decision D9).
#
# Exact pins for the whole transitive closure, not just pymdoccbor: the point of this tool is to be a check that
# does not move under us. `pip install -r docs/design/tools/requirements-verify.txt` reproduces it; bump a pin only
# together with a run over the recorded samples.
#
# Install (CI and locally):
#   python3 -m venv .venv-verify
#   .venv-verify/bin/pip install --quiet -r docs/design/tools/requirements-verify.txt --require-hashes=false
#
# Hashes are deliberately not pinned: `cryptography` and `cffi` ship per-platform wheels, so a hash file would have
# to carry every platform's wheel hash and would fail on the one it does not list. The versions are exact, which is
# what keeps the verification result reproducible.
